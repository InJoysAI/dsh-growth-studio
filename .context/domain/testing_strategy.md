## 📋 模块验收标准

### 模块 1: 运营驾驶舱与渠道矩阵

#### 场景 1: 渠道会话四态呈现
```gherkin
Given 用户已打开工作台
  And 微信公众号已在浏览器实例中完成扫码登录
  And B站尚未登录
When 用户查看渠道矩阵网格
Then 微信公众号卡片应显示绿色指示灯与"已认证就绪"状态
  And B站卡片应显示琥珀色指示灯与"需登录"状态
  And B站卡片应展示"去登录 ↗"按钮
```

#### 场景 2: 分发矩阵连通度统计
```gherkin
Given 工作台支持 2 个渠道
  And 其中仅 1 个渠道处于"已认证就绪"状态
When 用户查看"分发矩阵连通度"指标卡
Then 该指标应显示为 "1 / 2"
  And 不得显示为 "2 / 2"
```

#### 场景 3: 未知与无权限两态（BR-010）
```gherkin
Given 工作台尚未探测某渠道的会话状态
When 用户查看渠道矩阵网格
Then 该渠道应显示灰色指示灯与"未知 / 探测中"状态
  And 不得显示为"已认证就绪"

Given 某渠道账号已登录但未开通创作者权限
When 用户查看渠道矩阵网格
Then 该渠道应显示红色指示灯与"无权限"状态
  And 该渠道的"分发矩阵连通度"不计入分子
```

#### 场景 4: 驾驶舱头部引擎状态
```gherkin
Given 知识库中枢已正确配置且可连通
  And 浏览器引擎实例未启动
When 用户查看驾驶舱头部
Then 知识库中枢状态灯应为绿色
  And 浏览器引擎状态灯应为红色
```

#### 场景 5: 快捷行动组跳转
```gherkin
Given 用户当前位于运营驾驶舱
When 用户点击"✍ 新建多端物料"
Then 界面应切换至内容创作室
  And 创作输入框应获得焦点
```

### 模块 2: 内容日历与发布流水线

#### 场景 1: 内容状态五态流转
```gherkin
Given 一个排期项当前状态为"计划中"
When 用户依次推进该排期项状态
Then 状态应依次呈现为"撰写中" → "草稿就绪" → "已推草稿箱" → "已发布"
  And 每一步都应有对应的状态胶囊样式
```

#### 场景 2: 发布确认闭环（人工发布 + 回填 URL）
```gherkin
Given 一个排期项状态为"草稿就绪"
  And 用户已点击"一键预填至草稿箱"且预填成功
When 预填动作完成
Then 状态应变为"已推草稿箱"
  And 界面应展示"前往平台草稿箱 ↗"外链
  And 状态不得自动变为"已发布"

When 用户在平台后台人工完成发布
  And 回到工作台填入该平台真实 URL
Then 状态才应变为"已发布"
```

#### 场景 3: 未回填 URL 不得标记为已发布
```gherkin
Given 一个排期项处于"已推草稿箱"状态
  And 用户尚未填入任何平台 URL
When 用户查看该排期项状态
Then 状态应保持为"已推草稿箱"
  And 不应出现"已发布"标记
```

#### 场景 4: 排期导出至 Injoys 表格
```gherkin
Given 用户已生成未来 7 天的排期
When 用户点击"导出至 Injoys 表格"
Then 排期行应出现在 Injoys 表格中
  And 表格中的行内容应与工作台内的排期一致
```

#### 场景 5: 从 Injoys 表格导入排期
```gherkin
Given Injoys 表格中已存在若干排期行
When 用户执行"从 Injoys 表格导入"
Then 已有排期行应出现在工作台的排期看板中
```

#### 场景 6: 单渠道草稿的发布条件（BR-021）
```gherkin
Given 一个草稿只面向 1 个渠道
  And 该草稿状态为"已推草稿箱"
When 用户填入该渠道的有效平台 URL
Then 状态应变为"已发布"
```

#### 场景 7: 多渠道草稿部分回填（BR-021）
```gherkin
Given 一个草稿面向 2 个渠道
  And 该草稿状态为"已推草稿箱"
When 用户只为其中 1 个渠道填入有效 URL
Then 状态应**固定**停留在"已推草稿箱"
  And 不得变为"已发布"
  And 界面应能看出 2 个渠道中已回填 1 个
```

#### 场景 8: 多渠道草稿全部回填（BR-021）
```gherkin
Given 一个草稿面向 2 个渠道
  And 其中 1 个渠道已回填有效 URL
When 用户为剩余的 1 个渠道也填入有效 URL
Then 状态才应变为"已发布"
```

#### 场景 9: 已发布草稿新增未回填渠道须回退（BR-021）
```gherkin
Given 一个草稿状态为"已发布"，且其全部渠道均已回填
When 用户为该草稿新增 1 个尚未回填的渠道
Then 该草稿的 ContentDraft.status 应回退为"已推草稿箱"
  And 不得维持"已发布"
  And 关联排期项 ItemStatus 保持不变（回退不跨枚举）
```

#### 场景 10: 删除渠道后不得残留假已发布（BR-021）
```gherkin
Given 一个草稿已"发布"到 2 个渠道
When 用户删除其中 1 个渠道
Then 该渠道的发布凭据应被一并清除
  And 剩余渠道若已回填则应维持"已发布"，不得因残留凭据维持假的已发布
```

### 模块 3: 跨平台内容创作室

#### 场景 1: 物料生成与本地存盘
```gherkin
Given 用户位于内容创作室
  And 用户已输入本次更新特性、目标受众与基调风格
When 用户触发 AI 生成物料
Then 应生成结合产品知识库的多渠道物料
  And 物料应自动保存至本地草稿库
  And 重启工作台后该草稿仍可查看
  And 未经用户明确要求不得创建或更新 Injoys 文档
```

#### 场景 2: 当前草稿编辑与覆盖保存
```gherkin
Given 本地草稿库中存在一份草稿
When 用户手动编辑正文与标题并再次存盘
Then 应覆盖保存当前草稿内容
  And MVP 不创建历史快照或提供历史查看与恢复
```

Given 用户已生成一篇公众号图文物料
When 用户打开公众号图文卡片模拟器
Then 应展示朋友圈分享卡片预览
  And 应展示公众号文章详情预览
  And Markdown 代码应高亮显示

#### 场景 4: B站视频元数据卡片模拟器
```gherkin
Given 用户已生成一份 B站视频物料
When 用户打开 B站视频元数据卡片模拟器
Then 应展示 3 套候选标题
  And 应展示结构化简介
  And 应展示标签词云与分区选择
```

#### 场景 5: 一键复制物料
```gherkin
Given 用户已生成一份渠道物料
When 用户点击"一键复制物料"
Then 剪贴板内容应与预览中的物料一致
```

### 模块 4: 草稿箱预填（安全边界）

#### 场景 1: 公众号与 B站真实预填
```gherkin
Given 微信公众号与 B站均处于"已认证就绪"状态
  And 存在一份"草稿就绪"状态的物料
When 用户点击"BrowserOS 一键预填至草稿箱"
Then 该草稿应真实出现在微信公众号后台草稿列表中
  And B站视频标题与简介应真实填入创作者页面
  And 用户应收到草稿直达验证链接
```

#### 场景 2: 预填失败不虚报成功
```gherkin
Given 某渠道处于"需登录"状态
When 用户点击"一键预填至草稿箱"
Then 界面应提示需要先登录
  And 不得显示"预填成功"
  And 排期状态应保持为"草稿就绪"
```

#### 场景 3: 绝不自动确认发布（铁律）
```gherkin
Given 任一渠道的草稿已预填完成
When 预填流程结束
Then 工作台不得代替用户点击平台的"正式发布 / 群发"按钮
  And 界面应提示"草稿已填好，请人工检查预览后点击发布"
  And 最终发布动作必须由用户在平台后台手工完成
```

### 模块 5: 舆情监控与需求提炼

#### 场景 1: 真实评论抓取
```gherkin
Given 用户在公众号或 B站已有已发布的内容
When 用户执行评论抓取
Then 应抓取到真实用户评论文本
  And 评论内容不得为示例或占位数据
```

#### 场景 2: 需求聚类与沉淀
```gherkin
Given 已抓取到不少于 10 条真实用户评论
When 用户触发需求提炼
Then 应聚类出 Bug 与功能建议
  And 应结构化沉淀至 Injoys 需求池
  And 应至少提炼出 1 条需求
```

#### 场景 3: 复盘报告基于真实指标
```gherkin
Given 用户已采集到多平台真实指标
When 用户生成周度运营增长分析报告
Then 报告中的数字应与指标大屏一致
  And 数据不足的部分应如实标注，不得用估算值补齐
```

#### 场景 4: 平台真实零值与采集失败严格区分（BR-050 / BR-051）
```gherkin
Given 某平台真实返回该指标为 0
  And 另一平台该指标采集失败
When 用户查看指标卡
Then 平台真实返回的 0 应正常显示为 0
  And 采集失败的平台应显示"暂无数据"
  And 两者在界面上必须可区分，不得都显示为 0
```

#### 场景 5: 部分渠道采集失败时汇总值为空（BR-050）
```gherkin
Given "全网曝光/播放总量"应采集 2 个渠道
  And 仅 1 个渠道采集成功
When 用户查看该汇总指标卡
Then 汇总值应显示"暂无数据"
  And 不得只汇总已成功的渠道并冒充实"全网总量"
  And 界面应能看出哪些渠道未被采集
```

#### 场景 6: 历史不足时环比为空（BR-052）
```gherkin
Given 本地历史指标快照不足以覆盖完整对比窗口
When 用户查看指标卡的环比走势
Then 环比应显示为空
  And 不得编造环比结论
```

> **场景 4 / 5 / 6 的当前自动化范围**：`tests/overview-metrics.spec.ts` 验证宿主平台覆盖门、真实零值、互动严格空值、本周筛选与无历史空环比；`tests/overview-window-passthrough.spec.ts` 验证 RPC 请求窗口穿透；`tests/metrics-window.spec.ts` 验证实际采集器的窗口字段，包括成功 `live` 分支在 `7d` / `30d` 下的精确起止值、采集时刻，以及窗口不可证实结果不进入汇总。完整覆盖和零值的正向汇总通过显式测试数据验证，不表示当前 `live` 页面已能提供该周期增量。宿主测试也不能替代场景中的驾驶舱 UI 验收，历史快照持久化仍归 TD-010 / `feat-storage-metrics-snapshot`。

#### 场景 7: 评论抓取为空不伪造（BR-054）
```gherkin
Given 已发布内容暂无用户评论
When 用户执行评论抓取
Then 应提示暂无可分析评论
  And 不得使用示例或占位评论冒充真实反馈
```

### 模块 6: 引擎与平台配置

#### 场景 1: 连通性测试与延迟诊断
```gherkin
Given 用户已填写知识库接入地址与凭证
When 用户点击一键连通性测试
Then 应展示连通结果与延迟数值
```

#### 场景 2: 凭证显隐切换
```gherkin
Given 用户已保存知识库接入凭证
When 用户查看凭证字段
Then 凭证应默认以掩码形式显示
  And 用户点击后应可切换为明文查看
```

#### 场景 3: 全局运营策略即时生效
```gherkin
Given 用户在工作台配置中修改默认产品名称
When 用户保存设置
Then 新建物料应以新的产品名称生成
  And 无需重启工作台即可生效
```

#### 场景 4: 本地草稿存储目录配置
```gherkin
Given 用户配置页中展示了本地草稿存储目录
When 用户将目录更改为一个新的可用位置并保存
Then 后续新发起的草稿操作应写入新目录
  And 界面应提示"新目录对后续操作生效；正在进行的保存仍写入原目录。旧草稿不会自动迁移"
```

#### 场景 5: BrowserOS 能力管理默认八项与启停保持（BR-074）
```gherkin
Given 首次使用或旧配置缺少能力字段
When 打开引擎策略配置 → BrowserOS 浏览器引擎 → 能力管理
Then 默认八项 tabs/navigate/snapshot/act/read/grep/wait/upload 均启用
  And 其余实际暴露工具默认关闭

Given 用户关闭某项默认能力并保存后重启
When 再次进入能力管理页
Then 该能力仍保持关闭，不因重启重置
```

#### 场景 6: 未暴露工具不列出（BR-074）
```gherkin
Given 某工具当前连接未提供
When 打开能力管理页
Then 该工具不出现于清单（消失的工具就消失）
  And 未连接通过引擎状态灯（connected）表达
```

#### 场景 7: 两层开关的执行拒绝（BR-074）
```gherkin
Given 一个 ops_* 运营工具调用 BrowserOS 底层工具
When 运营工具开关关闭、而所调用的 BrowserOS 能力开关开启
Then 执行被拒绝
  And 返回「已禁用」语义，不执行底层工具

Given 一个 ops_* 运营工具调用 BrowserOS 底层工具
When 运营工具开关开启、而所调用的 BrowserOS 能力开关关闭
Then 执行被拒绝
  And 返回「已禁用」语义，不执行底层工具
```

#### 场景 8: 两层开关同时开启时正常执行（BR-074）
```gherkin
Given 一个非默认暴露的 BrowserOS 工具已被用户手动启用
  And 经 ops_* 调用时，该运营工具开关也已启用
  And BrowserOS 连接可用且提供了该工具
When 该工具被调用
Then 正常执行
  And 仍受「不自动发布 / Cookie 零外发」业务守卫约束
```

> **来源说明**：场景 4 提示文案引自 `criterion §3.5`（非 PRD 原文）；场景 5/6/7/8 引自 PRD §5.7.1（v1.2.1 能力管理，含两层开关必须同时满足）。

### 模块 7: AI 运营工具中枢与调试试炼沙箱

#### 场景 1: 工具按生命周期分类呈现（BR-040）
```gherkin
Given 用户位于 AI 工具中枢
When 用户查看工具目录
Then 工具应按"策划与选题 / 创意与生成 / 分发与执行 / 分析与监听 / 系统与调度"五类分组
  And 每组应包含属于该类的工具
```

#### 场景 2: 工具清单不含自动发布工具（BR-022 铁律）
```gherkin
Given 用户位于 AI 工具中枢
When 用户查看全量工具目录
Then 目录中**不得**存在任何自动确认发布的工具
  And 分发类工具应仅止步于"预填至草稿箱"
```

#### 场景 3: 单步调试沙箱（BR-041）
```gherkin
Given 用户位于可视化单步调试沙箱
When 用户填写参数并运行某个工具
Then 应展示该工具的 **卡片渲染效果**（按该工具的输出形态渲染为业务卡片）
  And 应展示该工具的结构化返回结果
  And 应展示执行耗时
  And 无需经过多轮对话即可完成单步运行
```

### 模块 8: 热点雷达与知识沉淀

#### 场景 1: 热点采用跳转至创作室（BR-060）
```gherkin
Given 用户在热点雷达中看到一条与产品领域相关的选题
  And 该选题显示热度指数与契合平台
When 用户点击"采用此选题创作 ➔"
Then 界面应**直接切入创作室**
  And 创作室应已预填该选题的标题与基调
  And **不得**跳转到排期日历生成
```

#### 场景 2: 物料沉淀至 Injoys 知识文档（BR-033）
```gherkin
Given 用户已生成一份渠道物料
When 用户点击"沉淀至 Injoys 知识文档"
Then 该物料应出现在 Injoys 知识文档中
  And 可在 Injoys 侧检索到该文档
```

#### 场景 3: 知识库未连通时沉淀不可用（BR-073）
```gherkin
Given 知识库中枢未连通
When 用户点击"沉淀至 Injoys 知识文档"
Then 界面应明确提示该能力不可用
  And 不得显示"沉淀成功"
```

## 配置保存专项验收补充

依据已归档提案 `fix-config-save-error-swallow` 的 `specs/ops-config/spec.md` 与架构源文档 §3.10.2；这是配置文件保存失败的新增专项覆盖，不把模块 6 场景 4 冒认为原本已经包含此分支，也不新造业务规则编号。

### 场景 A：配置文件无法保存时当场提示失败
```gherkin
Given 用户的配置存储目录不可写或该目录路径被普通文件占用
When 用户提交新的非空接入地址与凭证
Then 配置页应显示非空中文保存失败说明，不应显示保存成功
  And 不向用户展示底层技术错误或调用栈
  And 当前运行中的接入配置保留新提交的非空值，不因写盘失败回滚
  And 下次重启读取实际已保存的配置，不能承诺失败的配置已持久保存
```

### 场景 B：可写配置保存成功且确实持久化
```gherkin
Given 用户的配置存储目录可写
When 用户提交新的接入配置并保存
Then 保存应成功，配置文件中应有提交的新凭证
  And 运行中的接入配置即时生效，无需重启
```

### 场景 C：不可用草稿目录在更改配置前被拒绝
```gherkin
Given 用户选择的草稿目录不可写或不能创建
When 用户提交该草稿目录
Then 应在更改配置前提示草稿目录不可用
  And 不应先显示配置保存成功、再在后续保存草稿时才发现目录失败
```

自动化证据映射：`tests/ops-manager.spec.ts` C1/C2 覆盖场景 A 的真实文件系统失败与失败结果，C1 同时保护中文说明/不泄技术细节/失败目录；C3 实际读取配置文件覆盖场景 B 的持久化，C4 分别读取客户端与配置存储，保护失败后非空字段一致及不回滚；C5 保护场景 C 与配置写盘失败的不同分类，C6 保护其他异常不被错分为存储错误。空串提交的既有分裂不在一致性保证范围内（见 `api_strategy.md` §3.6）。

验收边界：上述自动化证据不是 GUI 手动验收，也不是实际重启测试；归档 tasks 4.3.2 的配置页手测仍未完成。本补充不将其勾选为通过。POSIX 只读文件本身不足以触发保存失败，采用目录权限/路径占用的真实触发方式，权限位不生效的环境显式跳过相关权限用例。
