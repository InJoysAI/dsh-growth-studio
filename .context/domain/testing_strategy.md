## 📋 模块验收标准

### 模块 1: 运营驾驶舱与渠道矩阵

#### 场景 1: 渠道会话四态呈现
```gherkin
Given 用户已打开工作台
  And 微信公众号已在浏览器实例中完成扫码登录
  And B站尚未登录
When 用户查看渠道矩阵网格
Then 微信公众号卡片应显示绿色指示灯与"已认证就绪"状态
  And B站卡片应显示琥珀色指示灯与"需登录"状态
  And B站卡片应展示"去登录 ↗"按钮
```

#### 场景 2: 分发矩阵连通度统计
```gherkin
Given 工作台支持 2 个渠道
  And 其中仅 1 个渠道处于"已认证就绪"状态
When 用户查看"分发矩阵连通度"指标卡
Then 该指标应显示为 "1 / 2"
  And 不得显示为 "2 / 2"
```

#### 场景 3: 驾驶舱头部引擎状态
```gherkin
Given 知识库中枢已正确配置且可连通
  And 浏览器引擎实例未启动
When 用户查看驾驶舱头部
Then 知识库中枢状态灯应为绿色
  And 浏览器引擎状态灯应为红色
```

#### 场景 4: 快捷行动组跳转
```gherkin
Given 用户当前位于运营驾驶舱
When 用户点击"✍ 新建多端物料"
Then 界面应切换至内容创作室
  And 创作输入框应获得焦点
```

### 模块 2: 内容日历与发布流水线

#### 场景 1: 内容状态五态流转
```gherkin
Given 一个排期项当前状态为"计划中"
When 用户依次推进该排期项状态
Then 状态应依次呈现为"撰写中" → "草稿就绪" → "已推草稿箱" → "已发布"
  And 每一步都应有对应的状态胶囊样式
```

#### 场景 2: 发布确认闭环（人工发布 + 回填 URL）
```gherkin
Given 一个排期项状态为"草稿就绪"
  And 用户已点击"一键预填至草稿箱"且预填成功
When 预填动作完成
Then 状态应变为"已推草稿箱"
  And 界面应展示"前往平台草稿箱 ↗"外链
  And 状态不得自动变为"已发布"

When 用户在平台后台人工完成发布
  And 回到工作台填入该平台真实 URL
Then 状态才应变为"已发布"
```

#### 场景 3: 未回填 URL 不得标记为已发布
```gherkin
Given 一个排期项处于"已推草稿箱"状态
  And 用户尚未填入任何平台 URL
When 用户查看该排期项状态
Then 状态应保持为"已推草稿箱"
  And 不应出现"已发布"标记
```

#### 场景 4: 排期导出至 Injoys 表格
```gherkin
Given 用户已生成未来 7 天的排期
When 用户点击"导出至 Injoys 表格"
Then 排期行应出现在 Injoys 表格中
  And 表格中的行内容应与工作台内的排期一致
```

#### 场景 5: 从 Injoys 表格导入排期
```gherkin
Given Injoys 表格中已存在若干排期行
When 用户执行"从 Injoys 表格导入"
Then 已有排期行应出现在工作台的排期看板中
```

### 模块 4: 草稿箱预填（安全边界）

#### 场景 1: 公众号与 B站真实预填
```gherkin
Given 微信公众号与 B站均处于"已认证就绪"状态
  And 存在一份"草稿就绪"状态的物料
When 用户点击"BrowserOS 一键预填至草稿箱"
Then 该草稿应真实出现在微信公众号后台草稿列表中
  And B站视频标题与简介应真实填入创作者页面
  And 用户应收到草稿直达验证链接
```

#### 场景 2: 预填失败不虚报成功
```gherkin
Given 某渠道处于"需登录"状态
When 用户点击"一键预填至草稿箱"
Then 界面应提示需要先登录
  And 不得显示"预填成功"
  And 排期状态应保持为"草稿就绪"
```

#### 场景 3: 绝不自动确认发布（铁律）
```gherkin
Given 任一渠道的草稿已预填完成
When 预填流程结束
Then 工作台不得代替用户点击平台的"正式发布 / 群发"按钮
  And 界面应提示"草稿已填好，请人工检查预览后点击发布"
  And 最终发布动作必须由用户在平台后台手工完成
```

Then 应抓取到真实用户评论文本
  And 评论内容不得为示例或占位数据

```gherkin
Given 已抓取到不少于 10 条真实用户评论
When 用户触发需求提炼
Then 应聚类出 Bug 与功能建议
  And 应结构化沉淀至 Injoys 需求池
  And 应至少提炼出 1 条需求
```

#### 场景 3: 复盘报告基于真实指标
```gherkin
Given 用户已采集到多平台真实指标
When 用户生成周度运营增长分析报告
Then 报告中的数字应与指标大屏一致
  And 数据不足的部分应如实标注，不得用估算值补齐
```

  And 界面应提示"新目录对后续操作生效；正在进行的保存仍写入原目录。旧草稿不会自动迁移"

## 🔒 安全与合规验收（业务层面）

| 验收项 | 业务要求（以 PRD 为准） | 验证方式 |
|--------|----------------------|---------|
| **人工发布控制权** | 严禁任何自动点击最终确认发布的行为，始终仅预填草稿 | 走完预填流程后，确认平台后台内容仍为草稿状态，工作台未触发发布 |
| **发布凭据真实性** | 只有回填平台真实 URL 后才可标记为"已发布" | 不回填 URL 时状态停留在"已推草稿箱" |
| **指标真实性** | 采集失败或平台不支持的指标不得按 0 或估算值展示 | 断开采集条件后确认指标显示"暂无数据" |
| **数据本地化** | 草稿保存在用户本机，不上传到服务器；会话数据不向第三方上报 | 检查草稿仅存在于本地配置目录 |
| **凭证保密** | 凭证不在界面明文常驻，用户可控显隐 | 查看配置页默认显示为掩码，点击后可切换为明文 |

> 加密算法、防注入手段等实现方式属于 `criterion.md` 与架构文档，不在此重复。

## 📝 UAT 流程

| 阶段 | 环境 | 执行人 | 内容 |
|------|------|--------|------|
| **Alpha 验收** | 本地开发环境（未接入真实平台） | 开发者 | 核心功能符合设计预期，界面交互与状态流转正常 |
| **Beta 验收（Live 实测）** | 真实浏览器实例 + 真实平台账号 | 开发者 | 在真实环境中登录公众号与 B站，完成预填 → 人工发布 → 回填 URL → 指标采集全链路 |
| **Sign-off** | 真实环境 | 产品负责人 | Phase 0 验收条件全部勾选通过后签字，进入 Phase 1 |

### Phase 0 Live 实测清单（来源：开发计划 §三 Phase 0 验收条件）

- [ ] 在浏览器实例中登录公众号与 B站后，工作台状态准确呈现"已认证就绪"
- [ ] AI 生成的公众号文章在本地生成持久化草稿，并支持二次编辑存盘
- [ ] 点击"预填草稿"，内容真实注入微信公众号后台，后台草稿列表可见该草稿
- [ ] 点击"预填草稿"，B站视频标题和简介真实填入创作者页面
- [ ] 人工发布后填入平台 URL，排期与草稿状态变为"已发布"
- [ ] 排期行能真实写入 Injoys 表格并读取回显

> ⚠️ Phase 0 交付结论（开发计划 §三）：部分整改已落实，仍有实现缺口；**修复后再进入真实环境验收**。
