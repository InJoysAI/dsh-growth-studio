### 风险清单

#### RISK-B001: 平台页面结构变动导致预填失效

| 属性 | 值 |
|------|-----|
| **类别** | 依赖风险 |
| **可能性** | 高 |
| **影响程度** | 高 |
| **风险等级** | 极高风险 |
| **负责人** | 产品负责人 |
| **描述** | 各平台创作者后台的页面结构随时可能调整，预填流程依赖平台页面，一旦变动即可能导致草稿填充失败或填充不完整 |
| **缓解措施** | 适配器按平台彻底解耦，单一平台变动不影响其他平台；预填失败必须如实报错而非静默跳过；建立预填失败的回退路径（一键复制物料，用户手工粘贴） |
| **应急预案** | 临时引导用户使用「一键复制物料」手工完成预填，同时修复对应平台适配器 |
| **来源** | PRD §5.4.3「一键复制物料」；开发计划 §五 3「DOM 变动与页面防护」 |

#### RISK-B002: 平台账号权限不足导致渠道不可用

| 属性 | 值 |
|------|-----|
| **类别** | 依赖风险 |
| **可能性** | 中 |
| **影响程度** | 中 |
| **风险等级** | 中风险 |
| **负责人** | 产品负责人 |
| **描述** | 用户账号可能已登录但未开通创作者权限或无发布权限，导致该渠道无法完成预填与指标抓取 |
| **缓解措施** | 会话状态专门保留"无权限"态并以红色指示灯呈现，让用户第一时间区分"未登录"与"无权限"，避免误判为工具故障 |
| **应急预案** | 引导用户前往平台开通创作者权限后再使用该渠道 |
| **来源** | PRD §5.2.1 四态生命周期第 4 态 |

#### RISK-B003: 海外平台合规与区域可达性差异

| 属性 | 值 |
|------|-----|
| **类别** | 合规风险 / 依赖风险 |
| **可能性** | 中 |
| **影响程度** | 高 |
| **风险等级** | 高风险 |
| **负责人** | 产品负责人 |
| **描述** | Phase 2 需接入 YouTube、X、Product Hunt、TikTok 四个海外平台，各平台的账号体系、内容政策与访问条件与国内平台差异较大，可能影响草稿预填与指标采集的可行性 |
| **缓解措施** | Phase 2 先以 PoC 验证浏览器侧可行性并输出可行性报告与边界定义，验证通过后再进入交付 |
| **应急预案** | 若某平台无法通过浏览器侧稳定支持，先降级为"物料生成 + 手工发布"，不承诺预填能力 |
| **来源** | PRD §七 Phase 2；开发计划 §三 Phase 2 开发任务 2 |

#### RISK-B004: 人工发布环节的体验断点

| 属性 | 值 |
|------|-----|
| **类别** | 市场风险 |
| **可能性** | 中 |
| **影响程度** | 中 |
| **风险等级** | 中风险 |
| **负责人** | 产品负责人 |
| **描述** | 产品坚持人工最终确认发布，用户需要在平台后台手工完成发布并回填 URL，这一环节若体验不顺（找不到草稿、忘记回填），会造成流水线状态与实际发布情况不一致 |
| **缓解措施** | 预填完成后提供草稿直达链接，减少用户在后台的寻找成本；状态保持"已推草稿箱"并在界面上持续可见，提示仍需回填 |
| **应急预案** | 允许用户手动修正排期状态，避免流程卡死 |
| **来源** | PRD §5.3.1 发布确认闭环、§5.4.3 安全约束 |

> ⚠️ **该风险为产品主动选择**：以人工确认换取发布安全，不得为消除该断点而引入自动发布能力（见 BR-022）。

#### RISK-B005: 多平台同步冲突造成数据覆盖

| 属性 | 值 |
|------|-----|
| **类别** | 依赖风险 |
| **可能性** | 中 |
| **影响程度** | 高 |
| **风险等级** | 高风险 |
| **负责人** | 产品负责人 |
| **描述** | Phase 3 规划支持本地排期与 Injoys 表格的实时双向同步；双向同步存在本地与云端同一条记录被同时修改而导致覆盖的风险 |
| **缓解措施** | Phase 0/1 严格限定为单向导出/导入，以本地数据为准，从源头避免冲突；双向同步推迟到 Phase 3 并明确冲突解决规则后再交付 |
| **应急预案** | 若双向同步规则未能收口，维持单向模式不升级 |
| **来源** | PRD §5.3.2 |

## 🧾 项目债务

> 项目层面的"妥协决策"（范围、流程、文档类）；技术债务见 `.context/architecture/risks_and_debt.md`。

### PD-001: 登录方式降级为统一浏览器实例手工扫码

| 属性 | 值 |
|------|-----|
| **类型** | 范围债务 |
| **严重性** | 中 |
| **描述** | 产品愿景中的内嵌扫码浮层、可视前台认证小窗与隔离登录环境（便于处理滑动拼图 / 双因素验证）被推迟到 Phase 2 做 PoC；Phase 0 先采用"引导用户在统一浏览器实例中手工扫码登录"的降级方案 |
| **影响** | Phase 0 用户需切换到浏览器实例完成登录，体验不如内嵌式顺畅；需滑动拼图或双因素验证的平台必须手工处理 |
| **偿还计划** | Phase 2 完成浏览器侧高级能力 PoC 后评估交付 |
| **来源** | PRD §5.2.3 |

### PD-002: 技能工坊与第三方扩展推迟交付

| 属性 | 值 |
|------|-----|
| **类型** | 范围债务 |
| **严重性** | 中 |
| **描述** | 5 大官方场景技能包推迟到 Phase 2；自定义技能包编辑器与第三方服务动态挂载推迟到 Phase 3。Phase 0 仅提供工具目录与单步调试沙箱 |
| **影响** | Phase 0 用户需自行组合工具调用，缺少开箱即用的场景化封装 |
| **偿还计划** | Phase 2 交付技能包，Phase 3 交付自定义编辑器 |
| **来源** | PRD §5.5.2、§5.5.3 |

### PD-003: Injoys 同步能力长期停留在单向

| 属性 | 值 |
|------|-----|
| **类型** | 范围债务 |
| **严重性** | 中 |
| **描述** | 双向同步与冲突仲裁推迟到 Phase 3，Phase 0–2 仅支持单向导出/导入 |
| **影响** | 用户在 Injoys 表格中的修改无法自动回流到工作台，需要手工重复导入 |
| **偿还计划** | Phase 3 引入行映射与冲突解决规则后交付 |
| **来源** | PRD §5.3.2 |

### PD-004: 焦点能力（图文草稿工作台界面）交付滞后于引擎能力

| 属性 | 值 |
|------|-----|
| **类型** | 流程债务 |
| **严重性** | 高 |
| **描述** | 当前客户端侧仅具备配置页与基础概览，草稿管理工作台界面尚未接入；用户尚无法在界面上完成"草稿管理 → 多变体编辑 → 预填入口"的可视化操作 |
| **影响** | 工作台的核心用户体验（一屏掌控、所见即所得）在 Phase 0 无法完整兑现，产品吸引力提升目标受限 |
| **偿还计划** | Phase 0 内补齐，属 Phase 0 交付范围 |
| **来源** | PRD §2.1 现状痛点；开发计划 §二 实现基线矩阵 |

### PD-005: 舆情与需求提炼能力延后至 Phase 1

| 属性 | 值 |
|------|-----|
| **类型** | 范围债务 |
| **严重性** | 中 |

| **偿还计划** | Phase 1 交付真实评论抓取与需求提炼 |
| **来源** | PRD §5.6、§七 Phase 1 |

## AI 引用指南

当 AI 进行项目规划时：
1. 检查依赖管理表，确认前置条件（尤其用户是否已提供知识库与表格）
2. 评估业务风险对交付时间的影响，特别关注 RISK-B001 与 RISK-B005
3. 在提案中标注相关风险缓解措施
4. **RISK-B004 的缓解措施不得被解读为可以引入自动发布**（见 BR-022）
