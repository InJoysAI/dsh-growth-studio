## 一、产品定位与范围

### BR-001: 产品定位
- **强制等级**: MUST
- **规则**:
  - 本产品是「独立开发者与个人产品专属的 AI 运营增长工作台」，面向 DeepSeek Harness 桌面端用户
  - 工作台承载「策—采—编—发—评」全链路：排期规划、知识库检索、多渠道文案生成、草稿箱预填、数据复盘与舆情
  - 产品覆盖国内 4 大渠道（微信公众号、哔哩哔哩、微信视频号、抖音）与海外 4 大渠道（YouTube、X、Product Hunt、TikTok）
- **来源**: PRD §2.2、§5.2.1
- **验收点**: 用户可在工作台内完成从选题排期到生成、预填的闭环；最终发布仍在平台后台人工完成（PRD §5.4.3 安全约束）

### BR-002: 分阶段渠道交付范围
- **强制等级**: MUST
- **规则**:
  ```
  IF 阶段 = Phase 0 THEN 交付渠道 = 微信公众号 + 哔哩哔哩
  ELSE IF 阶段 = Phase 1 THEN 渠道扩充至 微信视频号 + 抖音
  ELSE IF 阶段 = Phase 2 THEN 渠道扩充至 YouTube + X + Product Hunt + TikTok
  ```
  - 未在本阶段交付的渠道，不得出现在工作台的「就绪渠道」统计中
- **来源**: PRD §5.2.1、§七 里程碑规划
- **验收点**: Phase 0 工作台渠道矩阵只显示公众号与 B站两张平台卡片

### BR-003: 单产品运营视野
- **强制等级**: SHOULD
- **规则**:
  - 工作台头部显示当前正在运营的个人产品名（默认 `DeepSeek Harness`），并支持快速切换
  - 切换产品只改变内容生成所参考的知识范围，**不隔离**已有的排期、草稿、指标与会话数据
- **来源**: 产品识别与快速切换 → PRD §5.1.1；"不做数据隔离"为架构裁决 → `criterion §5.5`、架构文档 §3.10.3（**非 PRD 明文**，PRD 未规定产品切换的隔离语义）
- **验收点**: 切换产品名后，原有排期与草稿列表仍然完整可见

## 二、渠道会话状态管理

### BR-010: 会话四态生命周期
- **强制等级**: MUST
- **规则**:
  - 渠道会话状态必须呈现为四种状态之一，**不得简化为「已登录 / 未登录」两态**：
    1. `未知 / 探测中`：尚未查询或查询超时，灰色指示灯
    2. `需登录`：会话已失效或未登录，琥珀色指示灯
    3. `已认证就绪`：持有有效登录凭证，可执行草稿预填与指标抓取，绿色指示灯
    4. `无权限`：账号已登录但未开通创作者权限或无发布权限，红色指示灯
  - 仅「已认证就绪」状态可对外表述为"就绪"
- **来源**: PRD §5.2.1「会话状态四态生命周期规范」
- **验收点**: 未登录平台显示琥珀色灯与 `去登录 ↗` 按钮，不得显示为就绪

### BR-011: 未登录渠道的零阻碍引导
- **强制等级**: MUST
- **规则**:
  ```
  IF 渠道状态 = 需登录
  THEN 该渠道卡片必须展示 `去登录 ↗` 快捷外链
  ```
  - 用户点击后可直达该平台的登录入口
- **来源**: PRD §六 3「零阻碍操作原则」
- **验收点**: 所有未登录渠道均可见 `去登录 ↗` 入口，点击可打开对应平台

### BR-012: 会话就绪度统计
- **强制等级**: MUST
- **规则**:
  - 「分发矩阵连通度」指标只统计状态为`已认证就绪`的渠道数（例如 `2 / 2`）
  - 处于`未知`、`需登录`、`无权限`的渠道不计入分子
- **来源**: PRD §5.1.2「核心指标卡」第 4 项
- **验收点**: 一个渠道未登录时，连通度显示为 `1 / 2` 而非 `2 / 2`

## 三、内容日历与发布流水线

### BR-020: 内容五态流转
- **强制等级**: MUST
- **规则**:
  - 排期项状态按以下顺序流转：
    ```
    计划中 (Planned) ➔ 撰写中 (Drafting) ➔ 草稿就绪 (Draft Ready)
        ➔ 已推草稿箱 (Prefilled) ➔ 已发布 (Published)
    ```
  - 每个状态在界面上以胶囊样式呈现，并展示对应状态文案
  - **排期状态只前向推进，不存在回退**（`calendar.updateStatus` 强制校验，`published` 亦不可经该接口写入）；
    草稿侧「新增未回填渠道回退为 `prefilled`」只作用于 `ContentDraft.status`，**不联动排期 `ItemStatus`**（见 BR-021 与 `criterion §4`）
- **来源**: PRD §5.3.1（五态与发布确认闭环）；前向推进与草稿侧重算为架构裁决（`criterion §4`、TAD §3.2.5 / §3.3.2）
- **验收点**: 排期项可依次切换五种状态，界面文案与图标一致；越级或回退流转被拒绝

### BR-021: 发布确认闭环（人工发布 + 回填 URL）
- **强制等级**: MUST
- **规则**:
  ```
  IF 草稿预填完成
  THEN 状态变为「已推草稿箱」，并展示 `前往平台草稿箱 ↗` 外链
  AND 状态不得自动流转为「已发布」

  IF 用户已在平台后台人工确认发布
  THEN 用户在工作台填入平台真实 URL
  AND 状态才变为「已发布」
  ```
  - 没有平台真实 URL 时，任何内容都不得标记为「已发布」
  - **全渠道条件（多渠道草稿）**：
    ```
    IF 草稿只面向 1 个渠道
    THEN 该渠道回填有效 URL 后即「已发布」

    IF 草稿面向多个渠道
    THEN 仅当**全部渠道**都回填有效 URL 后，整条草稿才变为「已发布」
    AND 部分渠道已回填时，状态**固定**停留在「已推草稿箱」，不新增中间态
    AND 已发布的**草稿**若**新增了未回填的渠道**，其 `ContentDraft.status` 须回退为「已推草稿箱」（不联动排期 `ItemStatus`）
    AND 渠道被删除后，其残留的发布凭据须一并清除，避免维持假的「已发布」
    ```
  - 渠道进度通过已回填的渠道集合体现，用户可看出"2 个渠道中已回填 1 个"
- **来源**: PRD §5.3.1「发布确认闭环」、§5.4.3 安全约束；全渠道不变量为架构裁决，详见 `criterion §4`
- **验收点**: 单渠道草稿回填后即「已发布」；双渠道草稿只回填 1 个仍为「已推草稿箱」，回填 2 个才「已发布」；已发布草稿新增渠道后其草稿状态回退（排期状态不变）

### BR-022: 预填操作的安全边界
- **强制等级**: MUST（铁律）
- **规则**:
  - 工作台**始终仅预填至平台草稿箱**，严禁任何自动点击最终确认发布的行为
  - 预填完成后必须提示用户"草稿已填好，请人工检查预览后点击发布"
  - 不提供任何形式的自动发布能力（无自动群发、无自动投稿）
- **来源**: PRD §5.4.3「安全约束」、§5.5.1 第 3 项注
- **验收点**: 全量工具清单中不存在自动发布类工具；预填结束后界面停留在等待人工确认

### BR-023: 排期计划的生成与调整
- **强制等级**: SHOULD
- **规则**:
  - 用户可通过「+ 生成 7 天排期日历」快捷创建未来 7 天的排期
  - 用户可确认排期后导出至 Injoys 表格，也可从 Injoys 表格导入已有排期行
- **来源**: PRD §5.1.1、§5.3.2
- **验收点**: 生成的 7 天排期可完整导出并在 Injoys 表格中查看

### BR-024: Injoys 排期同步的阶段口径
- **强制等级**: MUST
- **规则**:
  ```
  IF 阶段 = Phase 0 THEN 同步方式 = 单向导出 / 导入，以本地排期数据为准
  ELSE IF 阶段 = Phase 3 THEN 支持双向同步与冲突仲裁
  ```
  - Phase 0 不得对外宣称支持双向实时同步
- **来源**: PRD §5.3.2
- **验收点**: Phase 0 界面提供「导出至 Injoys 表格」与「从 Injoys 导入」两个独立动作

## 四、内容创作室

### BR-030: 物料生成与本地存盘
- **强制等级**: MUST
- **规则**:
  - 每次 AI 生成物料后自动保存为本地草稿，**草稿主数据保存在用户本机，不会自动上传**（用户主动"沉淀至 Injoys 知识文档"时才会发送到用户自己的 Injoys 空间，见 BR-NFR-002）
  - MVP 只保留当前草稿，支持正文手动编辑、标题与标签微调并覆盖保存；不提供历史查看、恢复或版本快照。保存成功后旧内容不再由产品保留，版本号仅用于并发控制
  - 草稿库在用户配置的本地目录中管理，用户可自行更改存放位置
- **来源**: PRD §5.4.1、§5.7 第 3 项
- **验收点**: 生成物料后可在草稿库中找到该草稿，重启工作台后草稿仍存在

### BR-031: 多渠道物料适配
- **强制等级**: MUST
- **规则**:
  - 一次内容创作应结合产品知识库，为各目标渠道生成适配的物料变体
  - 每个渠道变体包含该渠道所需字段：图文类含标题、作者、正文；视频类含标题、简介、标签、分区
- **来源**: PRD §5.4.1、§5.4.2
- **验收点**: 同一主题可同时产出公众号图文与 B站视频两套物料

### BR-032: 跨平台真实样式预览
- **强制等级**: SHOULD
- **规则**:
  ```
  IF 渠道 = 微信公众号 THEN Phase 0 提供朋友圈分享卡片与文章详情预览，Markdown 代码高亮
  IF 渠道 = 哔哩哔哩  THEN Phase 0 提供 3 套候选标题、结构化简介、标签词云、分区选择
  IF 渠道 = 微信视频号 / 抖音 THEN Phase 1 提供对应卡片模拟器
  IF 渠道 = X / Product Hunt THEN Phase 2 提供推文串与 Launch Kit 模拟器
  ```
  - 预览须尽量贴近平台真实展示样式，支持微调后即时反映
- **来源**: PRD §5.4.2
- **验收点**: 在模拟器中修改标题，预览卡片同步更新

### BR-033: 物料一键复制与知识沉淀
- **强制等级**: SHOULD（一键复制为 Phase 0 首版交付；沉淀入口延至 Phase 2，执行须用户显式触发）
- **规则**:
  - 提供「一键复制物料」，便于用户手工粘贴到其他位置（Phase 0 首版交付）
  - 提供「沉淀至 Injoys 知识文档」入口（**路线图调整：延至 Phase 2**，由 `feat-workbench-sink-to-injoys-doc` 交付；Phase 0 期间插件内无该入口，用户可在 Injoys 侧手工沉淀），但**仅在用户点击该操作或明确要求时执行**，生成/预览/本地保存本身不授权上传
- **来源**: PRD §5.4.3（两项均标 `[Phase 0 首版]`）；入口阶段调整见 `openspec/proposal-roadmap.md`（Phase 2）与 `fix-unauthorized-injoys-doc-write` 的「上游规划差异」
- **验收点**: Phase 0：复制后剪贴板内容与预览一致；Phase 2：沉淀入口存在，且仅在用户显式触发后写入 Injoys

## 五、AI 运营工具中枢

### BR-040: 工具生命周期分类
- **强制等级**: SHOULD
- **规则**:
  - 工具按运营生命周期分为五类呈现：
    1. **策划与选题**：排期规划、热点嗅探、关键词研究
    2. **创意与生成**：图文草稿、视频元数据、发布物料包、吸睛钩子
    3. **分发与执行**：多渠道草稿箱批量预填
    4. **分析与监听**：指标采集、复盘报告、评论抓取、需求提炼
    5. **系统与调度**：定时巡检注册、会话探活
- **来源**: PRD §5.5.1
- **验收点**: 工具中枢按上述五类分组展示，每组包含对应工具
- **标注语义（PRD v1.2.2）**: 工具后的「外部依赖」标注仅表示该工具调用/读取的外部能力，**不代表主数据存储位置，也不代表自动写入授权**（生成只存本地、Injoys 写入须显式触发）；工具名 `ops_*` 与客户端 RPC 方法名是两套入口，可共享领域服务、不必互相调用。

### BR-041: 可视化单步调试沙箱
- **强制等级**: SHOULD
- **规则**:
  - 用户可在工作台内直接填写参数运行单个工具
  - 沙箱实时展示卡片渲染效果、返回结果与执行耗时
- **来源**: PRD §5.5.3
- **验收点**: 在沙箱中运行一次工具后可见返回结果与耗时

### BR-042: 场景技能包与工具裁剪
- **强制等级**: SHOULD
- **规则**:
  ```
  IF 阶段 = Phase 2 THEN 提供 5 大官方内置技能包
      （新版本发布、全球出海、舆情监听、热点排期、多端改编）
  AND 每个技能包仅注入 4~6 个白名单工具
  ELSE IF 阶段 = Phase 3 THEN 支持自定义技能包编辑与第三方服务动态挂载
  ```
- **来源**: PRD §5.5.2
- **验收点**: 启用某个技能包后，可用工具范围收敛为该包白名单
- **⚠️ 名称口径说明**: 上述 5 个技能包名称**直接引自 PRD §5.5.2**（PRD 原文：「提供 5 大官方内置技能包（新版本发布、全球出海、舆情监听、热点排期、多端改编）」）。
  开发计划 §三 Phase 2 也列出 **5 项**（「新版本发布、日常干货长图文、短视频矩阵引流、出海 Product Hunt Launch、每周舆情复盘」），两边**数量一致、且都包含「新版本发布」**，但其余 4 个名称不同（PRD：全球出海/舆情监听/热点排期/多端改编；计划：日常干货长图文/短视频矩阵引流/出海 Product Hunt Launch/每周舆情复盘）。
  由于 `development_plan.md` 为**计划类文档、不从中抽取规则**，且 PRD 为业务规则的权威来源，**本规则以 PRD 的 5 项名称为准**。
  两组名称的映射关系需在 Phase 2 交付前由产品负责人确认；在确认前，提案**不得**自行改用开发计划中的名称，也不得把「数量一致」误读为「名称一一对应」。

## 六、舆情监控与数据复盘

### BR-050: 指标真实性与可空语义
- **强制等级**: MUST
- **规则**:
  - 工作台展示的阅读量、播放量、点赞、评论、分享、收藏等指标必须来自平台真实数据
  - 采集失败或平台暂不支持的指标显示为「暂无数据」，**不得按 0 展示，也不得估算填充**
  - 真实为零与「未采集到」在界面上必须可区分
- **来源**: PRD §5.1.2「核心指标卡」第 1 项、§5.6
- **验收点**: 平台未采集成功时，指标卡显示「暂无数据」而非 `0`

### BR-051: 曝光与播放的区分口径
- **强制等级**: MUST
- **规则**:
  - 图文 / 推文渠道使用「阅读曝光」口径
  - 视频渠道使用「播放量」口径
  - 「全网曝光/播放总量」为非去重累计人次，界面须标注该口径说明
- **来源**: PRD §5.1.2「核心指标卡」第 1 项
- **验收点**: 指标卡下方标注"全网非去重曝光与播放累计人次"

### BR-052: 互动与关注增长汇总
- **强制等级**: SHOULD
- **规则**:
  - 汇总真实点赞、评论、转发、收藏数与净增关注数（`totalFollowersDelta`）
  - 每个指标卡配备副标题与环比走势
  - **不新增 `leads` 字段，也不把净增关注等同于销售线索**（PRD v1.2.2 明确否认「线索转化」语义）
- **来源**: PRD §5.1.2「核心指标卡」第 2 项（v1.2.2 由「互动与线索转化」更名）
- **验收点**: 互动卡显示点赞、评论、转发、收藏与净增关注的分项数据

### BR-053: 排期履约流水展示
- **强制等级**: SHOULD
- **规则**:
  - 展示本周规划内容的进展（例如 `6 / 7 篇`），并区分已预填草稿数与待发数
- **来源**: PRD §5.1.2「核心指标卡」第 3 项
- **验收点**: 履约卡显示完成比例与各阶段数量拆分

### BR-054: 评论抓取与需求反哺闭环
- **强制等级**: MUST
- **规则**:
  ```
  IF 阶段 >= Phase 1
  THEN 从真实发布的图文与视频中抓取用户评论
  AND 将评论聚类提炼为 Bug 与功能建议
  AND 结构化沉淀至 Injoys 需求池
  ```
  - 反哺的需求必须来源于真实抓取的评论，不得使用占位或示例数据
- **来源**: PRD §5.6「用户声音与需求池」
- **验收点**: 抓取真实评论后，可在 Injoys 需求池中看到提炼出的至少 1 条需求

### BR-055: 复盘报告基于真实指标

- **规则**:
  - 周度 / 月度复盘报告须基于真实采集的指标计算
  - 数据不足时如实标注，不得用估算值补齐结论
- **来源**: PRD §5.6、§5.5.1 第 4 项
- **验收点**: 复盘报告中的数字与指标大屏一致

## 八、引擎与平台配置

### BR-070: 引擎连接状态可视
- **强制等级**: MUST
- **规则**:
  - 工作台须以绿灯/红灯标注知识库中枢的连通性
  - 须以状态灯标注浏览器引擎实例的连接状态
  - 用户可执行一键连通性测试并查看延迟诊断结果
- **来源**: PRD §5.1.1、§5.7 第 1、2 项
- **验收点**: 断开引擎后状态灯变红，重连后变绿

### BR-071: 接入凭证的用户可见管理
- **强制等级**: MUST
- **规则**:
  - 知识库接入的凭证字段支持显隐切换
  - 用户可配置接入地址、完整凭证与本地草稿存储目录
- **来源**: PRD §5.7 第 1、3 项
- **验收点**: 凭证默认以掩码显示，点击可切换为明文

### BR-072: 全局运营策略即时生效
- **强制等级**: SHOULD
- **规则**:
  - 用户可设置默认产品名称与调性基调，保存后即时生效
  - 设置变更无需重启工作台
- **来源**: PRD §5.7 第 4 项
- **验收点**: 修改默认产品名后，新建物料即以新名称生成

### BR-073: 未接入引擎时的能力降级
- **强制等级**: MUST
- **规则**:
  ```
  IF 知识库中枢未连通
  THEN 依赖知识库的能力（排期同步、文档沉淀、需求池反哺）明确提示不可用
  AND 不得返回看似成功的结果

  IF 浏览器引擎未连通
  THEN 依赖浏览器的能力（会话探活、草稿预填、指标与评论采集）明确提示不可用
  AND 不得返回看似成功的结果
  ```
- **来源**: PRD §5.1.1、§5.7（能力依赖关系）
- **验收点**: 引擎未接入时点击预填，界面提示不可用而非显示"预填成功"

### BR-074: BrowserOS 浏览器引擎能力管理
- **强制等级**: MUST
- **规则**:
  ```
  BrowserOS 能力开关只决定哪些底层浏览器工具可被调用
  默认八项（默认启用集，非上限）: tabs / navigate / snapshot / act / read / grep / wait / upload
  其余实际暴露工具默认关闭、可手动开启；不存在永久禁用项（shell/cmd 若暴露同样由用户管理）
  用户显式保存的启停选择优先于默认值，保存与重启均不重置
  能力清单只列出当前连接实际暴露的工具；未暴露工具不列出（消失的工具就消失），未连接经状态灯表达
  两层开关同时满足: 经 ops_* 工具调用 BrowserOS 时，运营工具与所调用的 BrowserOS 能力必须同时启用
  ```
  - **行为边界**：能力开关**不改变**「始终仅预填、人工最终发布、会话数据零外发、不虚报成功、不伪造指标」等业务守卫；启用 `act` 或脚本类工具不等于允许自动发布或外传 Cookie。
  - **Profile 展示规则**：BrowserOS 状态灯只展示连接状态，未连接时提示接入方式；BrowserOS 的 Profile 路径仅在现有连接能真实提供时展示，不推测、不硬编码。
- **来源**: PRD §5.7.1（v1.2.1 新增）、§5.1.1（v1.2.2 状态灯文案收窄）
- **验收点**: 默认八项启用；关闭后重启保持关闭；未暴露能力**不列出**（消失的工具就消失）

## 十、身份认证演进（产品愿景）

### BR-090: 登录方式的分阶段演进
- **强制等级**: SHOULD
- **规则**:
  ```
  IF 阶段 = Phase 0 THEN 用户在统一的浏览器实例中完成扫码登录
  ELSE IF 阶段 = Phase 2 THEN **开展可行性验证（PoC）**：验证内嵌扫码浮层、
      可视前台认证小窗、隔离登录环境三项设想是否可行
  AND 输出可行性报告与能力边界定义
  AND 实际交付范围**以验证结论为准**，验证不通过则不交付该能力
  ```
  - ⚠️ **不得把 Phase 2 的 PoC 表述为"已支持"或"将支持"**：PRD 将该节标注为「产品愿景 / Phase 2 PoC 验证」，其交付物是**可行性结论**，而非既定的功能承诺
  - Phase 0 须确保所有渠道共用同一个浏览器实例，避免出现"看似就绪实则失效"的假就绪
  - 需滑动拼图 / 双因素验证的平台在 Phase 2 验证通过前仍由用户在浏览器实例中手工完成
- **来源**: PRD §5.2.3（演进愿景，标注为 PoC 验证）、§七 Phase 2（验收标准为"PoC 报告确认可行性"）
- **验收点**: Phase 0 中渠道就绪状态与浏览器实例中的真实登录态一致；Phase 2 产出可行性报告与边界定义（而非功能上线）

## 十一、非功能性要求（PRD 明文条目补充摘要）

> 只摘取**用户可感知、且 PRD 写了明确数值或口径**的条目；并发模型、加密算法、存储方式等实现类要求不在此列。

> **业务影响摘要**：草稿与排期的**主数据**停留于用户本机、不会自动上传；用户主动触发的「导出至 Injoys 表格」「沉淀至 Injoys 知识文档 / 需求表」是业务功能，会发送到用户自己的 Injoys 空间；**只有会话数据（平台登录凭据）严格零外发**。接口凭证以掩码形式展示且不写入配置以外的位置。完整边界见 BR-NFR-002，实现层约束详见 `criterion §4`。

### BR-NFR-001: 能力覆盖范围
- **强制等级**: MUST
- **规则**: 产品最终覆盖国内 4 大平台 + 海外 4 大平台，共 8 个分发渠道
- **来源**: PRD §2.1 第 3 项、§5.2.1

### BR-NFR-002: 内容留存边界
- **强制等级**: MUST
- **规则**:
  - 草稿与排期的**主数据**保存在用户本机，不会自动上传到服务器
  - 用户主动触发的「导出至 Injoys 表格」「沉淀至 Injoys 知识文档」「需求沉淀至 Injoys 需求表」是**业务功能**，会把相应内容发送到用户自己的 Injoys 空间，不属于"外发"
  - **会话数据（平台登录凭据）严格不向任何第三方服务上报**
- **来源**: PRD §5.4.1（本地持久化）、§5.3.2（导出至 Injoys）、§5.4.3（沉淀至 Injoys）、§5.6（需求表）、§5.2.3（隔离登录环境）
- **备注**: 实现层约束详见 criterion §4

- **来源**: PRD §5.5.2

## AI 引用指南

当 AI 生成业务逻辑代码或创建提案时：
1. 首先查找对应的 BR-XXX 规则，并在提案中引用编号
2. 严格按照规则中的 IF-THEN 逻辑实现**业务行为**
3. 实现手段（存储、并发、接口、错误码等）以 `.context/criterion.md` 和 `.context/architecture/` 为准
4. 对于 MUST 级别规则，必须添加验证逻辑
5. 对于 SHOULD 级别规则，添加降级处理
6. **BR-021 / BR-022 为铁律**：任何提案不得引入自动确认发布的能力
