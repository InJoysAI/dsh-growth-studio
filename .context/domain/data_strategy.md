## 1. 关键平台指标列表

> 本产品的度量对象是**已发布内容在各平台的表现**，而非用户在工具内的行为埋点。

| 指标名称 | 采集时机（用户在做什么） | 需要记录的信息 | 业务价值 |
|---------|----------------------|--------------|---------|
| 阅读曝光 | 用户刷新大盘时，从图文 / 推文渠道采集 | 渠道、数值、采集时间 | 衡量图文内容的触达规模 |
| 播放量 | 用户刷新大盘时，从视频渠道采集 | 渠道、数值、采集时间 | 衡量视频内容的触达规模 |
| 点赞数 | 用户刷新大盘时采集 | 渠道、数值、采集时间 | 衡量内容认可度 |
| 评论数 | 用户刷新大盘时采集 | 渠道、数值、采集时间 | 衡量互动深度，也是舆情来源 |
| 转发 / 分享数 | 用户刷新大盘时采集 | 渠道、数值、采集时间 | 衡量内容的传播力 |
| 收藏数 | 用户刷新大盘时采集 | 渠道、数值、采集时间 | 衡量内容的长期价值 |
| 净增关注数 | 用户刷新大盘时采集 | 渠道、数值、采集时间 | 衡量账号增长效果 |
| 单条内容最高表现 | 用户刷新大盘时采集 | 渠道、内容标题 | 识别爆款，支撑复盘结论 |
| 评论原文 | 用户执行评论抓取时 | 渠道、评论文本、来源内容 | 提炼 Bug 与功能建议的唯一素材来源 |

> 来源：PRD §5.1.2、§5.6。

## 2. 所有指标都要记录的公共信息

> 只写业务上需要知道什么；字段名、类型与格式属于架构。

- 指标所属的**平台 / 渠道**
- 指标的**业务口径**（是"阅读曝光"还是"播放量"，两者不可混用）
- **采集时间**，用于环比对比
- **采集是否成功**（成功但与零值区分；失败必须标记为未采集）
- 指标所**对应的内容**（可定位到具体一篇内容或视频）

> 来源：PRD §5.1.2「核心指标卡」的口径说明与环比走势要求。

## 3. 数据治理与删除策略

| 治理领域 | 策略 |
|---------|------|
| **数据最小化** | 只采集运营决策所需的平台公开指标与用户公开评论；不采集平台账号的登录凭据内容 |
| **删除传播** | 用户可直接删除**当前本地草稿**（MVP 不创建或管理草稿版本快照），删除后本产品不保留当前草稿副本，也不自动清理用户可能已有的历史文件。对**已沉淀到 Injoys 的既有内容**（导出的排期行、沉淀的物料文档、反哺的需求条目）的删除传播，PRD 未作规定——**属未定义范围，本产品不承诺联动删除**，需由用户在 Injoys 侧自行处理。⚠️ 注：草稿删除入口为「生成侧既有能力」，PRD §5.4.1 仅定义编辑/覆盖保存、未明文赋予删除能力，此处「可直接删除」的契约口径以 `criterion §4` 数据删除契约为准，业务域不新增 PRD 未授权的承诺 |
| **数据导出** | 排期数据支持导出至 Injoys 表格；物料支持一键复制；复盘报告沉淀至 Injoys 文档 |
| **用途声明** | 采集到的数据用于本机的工作台展示、复盘计算与需求提炼；用户主动触发的导出/沉淀会发送到用户自己的 Injoys 空间（属业务功能）；**会话数据不向任何第三方服务上报** |
| **审计留痕** | PRD 未作要求（PRD 未提供） |

> 来源：PRD §5.4.1（草稿本地持久化）、§5.3.2（导出至 Injoys 表格）、§5.4.3（一键复制 / 沉淀至 Injoys 知识文档）、§5.2.3（会话隔离）。
> **业务影响摘要**：物料与排期的**主数据**只存在于用户本机，不会自动上传；用户主动触发的「导出至 Injoys 表格」「沉淀至 Injoys 知识文档 / 需求表」属于业务功能，会把相应内容发送到用户自己的 Injoys 空间。**只有会话数据（登录凭据）是严格零外发**。实现层约束详见 `criterion §4`。

## 4. 核心指标定义

| 指标 | 计算公式 / 口径 | 数据源 |
|------|---------------|--------|
| **总曝光/播放量** | 各渠道曝光与播放的**非去重累计人次**之和 | 各平台创作者后台数据大屏 |
| **互动与关注增长** | 各渠道真实点赞 + 评论 + 转发 + 收藏 + 净增关注之和（不新增 leads 字段） | 各平台创作者后台数据大屏 |
| **排期履约流水** | 本周已推进内容数 / 本周规划内容总数（例如 `6 / 7 篇`），并拆分已预填数与待发数 | 本地排期数据 |
| **分发矩阵连通度** | 处于「已认证就绪」状态的渠道数 / 支持的渠道总数（例如 `2 / 2`） | 浏览器实例的渠道会话探测结果 |
| **环比走势** | 当前周期指标相对上一周期的变化 | 本地保存的历史指标快照 |

**口径要点（PRD 明文）**：

- 图文 / 推文渠道取**阅读曝光**，视频渠道取**播放量**，二者是不同口径，不可混为一谈。
- 总曝光/播放量是**非去重**的累计人次，界面须标注此说明。
- 采集失败或平台暂不支持的指标：**值为空（显示"暂无数据"），不按 0 计算，也不估算填充**。
- 真实返回的 `0` 是有效值，与"采集失败"必须严格区分。
- 历史数据不足以覆盖完整对比窗口时，环比走势应显示为空，不得编造。

> 来源：PRD §5.1.2；实现层口径详见 `.context/criterion.md` §4「指标真实性」。

## 5. 数据质量要求（业务口径）

> 埋点 / 采集的 SDK、上报通道、校验工具等实施规范属于 `.context/architecture/`，不写在这里。仅记录业务要求。

> **业务影响摘要**：指标采集与展示的落地方式对本目录不可见；用户可感知的结果是"数据来自平台真实表现、缺失时显示暂无数据"。实现层口径详见 `criterion §4`。

- **不得伪造**：任何展示给用户的指标都必须来自平台真实数据；README 与 PRD 均强调"无虚假数据"是 Phase 0 的验收关键标准。
- **缺失可辨识**：未采集成功的指标必须让用户看得出来是"暂无数据"，而不是误以为业务表现为零。
- **汇总口径诚实**：应采集的渠道未全部成功时，不得只汇总已成功的部分并冒充实"全网总量"。用户可感知的结果是"没有拿到全部渠道，就不给一个看起来像全网的数字"。覆盖范围的标注方式为**实现层口径，详见 `criterion §4`**，本文件不复述。
- **评论素材真实**：需求提炼必须基于真实抓取的评论，不得使用示例或占位数据。
- **可回溯**：用户应能看出指标的采集时间，以判断数据新鲜度。

> 来源：PRD §七 Phase 0 验收关键标准（"无虚假数据"）、§5.1.2、§5.6。

## 6. 里程碑与时间线

| 阶段 | 时间 | 交付内容 | 验收标准 |
|------|------|---------|---------|
| **Phase 0** | M0 | 真实采集公众号与 B站大屏指标（区分阅读/播放，允许为空） | 指标来自真实平台；无虚假数据；缺失项显示为暂无数据 |
| **Phase 1** | M1 | 跨平台真实评论抓取与需求聚类反哺；基于真实数据的增长复盘报告 | 抓取不少于 10 条真实评论，提炼至少 1 条需求并输出为表格 |
| **Phase 2** | M2 | 出海平台指标纳入采集范围 | 出海平台草稿生成与预填；PoC 报告确认可行性 |
| **Phase 3** | M3 | Injoys 复杂双向同步与冲突解决；批量任务进度可恢复 | 多端双向协同零数据冲突，长任务可监控中断重试 |

> 来源：PRD §七 实施里程碑规划。
