# ADR-004: 本地 JSON 为黄金主数据源，Injoys 单向导出

**状态**: Accepted
**日期**: 2026-10-15（源文档 TAD v1.4.5、PRD 基线 v1.2.2）
**决策者**: N/A – 源文档未提供

---

## 上下文 (Context)

工作台需要持久化三类数据：草稿（`ContentDraft`）、排期（`CalendarItem`）、指标历史（`PlatformMetrics`）。同时 Injoys 提供了 Spreadsheet 与 Document 能力，可承载排期表与知识文档。

**当前面临什么问题？**

- 数据应存本地还是存 Injoys？
- 若两边都可写，**冲突如何解决**？
- 个人开发者场景下，双向实时同步的复杂度是否值得？

---

## 决策驱动因素 (Decision Drivers)

- **单机可用性**：即使 Injoys 不可用，工作台也必须能正常工作
- **避免数据覆盖**：双向同步若做不好会**静默丢数据**，危害远大于收益
- **实现成本**：个人项目，无运维预算
- **离线优先**：本地写完即可用，不依赖网络往返
- **契约一致性**：`publishedUrls`、并发版本号等强约束状态需在**可信的本地存储**上维护

---

## 备选方案 (Considered Options)

### 方案 A: Injoys 作为主数据源

**描述**：排期与草稿直接读写 Injoys Spreadsheet / Document。

**优点**:
- 天然多端可见（网页可访问）
- 无需本地文件管理

**缺点**:
- **强依赖网络**：Injoys 不可用时工作台完全不可用
- 无本地原子写与写锁保证，难以维护状态不变量（如全渠道 `published` 判定）
- 当前文件原子替换、写锁、`expectedVersion` 乐观锁等机制无处落地
- 令牌未配置时功能全面瘫痪

### 方案 B: 本地为黄金主数据源 + Injoys 单向导出（**采用**）

**描述**：
- 本地 `$DSH_HOME/growth-studio/` 为排期与草稿的**黄金主数据源（SSoT）**；
- 通过 `InjoysClient` 调用 `spreadsheet.applyOperations` 将排期**单向写入** Injoys Spreadsheet；
- 支持通过 `spreadsheet.read` **导入**已存在的排期（`workbench.importCalendar`）；
- **不做**复杂的实时双向冲突解决，以避免数据覆盖；
- 导出以 `externalRowId` 为幂等键（更新而非重复插入）。

**优点**:
- **单机优先**：无 Injoys 也能完整工作
- **本地可做强保证**：原子写（临时文件 + rename）、串行写锁、`expectedVersion` 乐观锁；MVP 只保留当前草稿
- **冲突面收窄**：仅有"显式导入"这一条回流路径，规则可穷举枚举
- **本地状态优先**：导入不覆盖已 `prefilled` / `published` 项的状态与 `publishedUrl`

**缺点**:
- Injoys 侧的手工修改不会自动回流，需显式导入
- 用户需理解"本地是主"的心智模型

### 方案 C: 双向实时同步（LWW + 冲突合并）

**描述**：本地与 Injoys 双向实时同步，最后修改者胜出。

**优点**:
- 任一端的修改都能生效

**缺点**:
- **复杂度极高**：需行级 ID 映射表、时间戳版本、冲突行拆分标记
- **静默丢数据风险**：LWW 会无声地覆盖另一端的数据
- 超出 Phase 0 的资源与收益比

---

## 决策 (Decision)

**我们决定采用**: **方案 B —— 本地主数据 + 单向导出（Phase 0 降级策略）**

理由：

1. **可用性优先**：本地优先意味着 Injoys 故障不影响核心工作流；
2. **数据安全优先于同步便利**：方案 C 的静默覆盖风险是个人项目难以承受的，源文档明确选择"不做复杂的实时双向冲突解决，避免数据覆盖"；
3. **强约束需要可信存储**：发布状态不变量、当前草稿原子写与写锁建立在本地文件系统上；MVP 不增加草稿历史；
4. 保留了回流通道（显式导入），但把规则收窄到可穷举、可测的程度。

---

## 后果 (Consequences)

### 正面影响

- **离线可用**：Injoys 未配置或故障时，排期与草稿仍可正常管理
- **强一致性可控**：本地原子写 + 串行写锁 + 乐观锁
- **导出幂等**：重复导出同一周期不产生重复行（依据 `externalRowId`）
- **导入规则明确**：五条冲突规则可枚举、可测试
- **本地状态优先**：导入**不覆盖**已 `prefilled` / `published` 项的状态与 `publishedUrl`

### 负面影响

- Injoys 表格侧的手工编辑**不会自动回流**
- `externalRowId` 未回写前重复导出可能产生重复行（需先完成导出再回写）
- 双向同步能力延后到 Phase 3

### 风险

| 风险 | 缓解措施 |
|------|---------|
| 用户在 Injoys 侧改了表格，误以为已同步 | 文档与 UI 明示"本地为主数据源"；显式导入动作可用 |
| 导入覆盖本地真实发布结果 | 规则 4：导入**不覆盖**本地已 `prefilled` / `published` 项的状态与 `publishedUrl` |
| 导入部分失败被误报为全量成功 | 规则 5：失败时**不回滚已成功项**，如实返回已导入计数与 `conflicts` |
| 排期行重复 | 幂等键 `externalRowId`；无该键时按 `(date, platform, topic)` 三元组匹配 |
| 令牌未配置时误报"认证失败" | `injoys.test` 须返回明确的"尚未配置令牌"提示，**不得**发出请求并谎报认证失败 |

---

## 合规性 (Compliance)

此决策的执行要求：

- 本地 `$DSH_HOME/growth-studio/` **必须**作为排期与草稿的黄金主数据源
- 导出**必须**以 `externalRowId` 为准做**更新而非重复插入**，成功后**必须**在本地回写该 ID
- 导入**必须**遵守五条冲突与重复导入规则
- 导入**必须不覆盖**本地已 `prefilled` / `published` 项的状态与 `publishedUrl`
- 导入失败**必须**如实返回计数与错误，⛔ **不得**谎报全量成功
- ⛔ **不得**在 Phase 0 实现双向实时同步
- ⛔ **禁止**绕过 `config-store` / `draft-store` 模块直接操作文件
