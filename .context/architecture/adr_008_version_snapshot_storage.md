# ADR-008: MVP 只保留当前草稿，不提供历史版本与快照

**状态**: Accepted（2026-10-16 用户裁决替代原独立快照与恢复方案）
**日期**: 2026-10-16
**决策者**: 项目用户（本次会话明确授权手工同步）

## 上下文 (Context)

原方案把当前草稿与独立快照同时写入，并支持历史查看和恢复。
它引入了恢复发布凭据的规则，以及两个文件之间失败时的一致性处理，超出 MVP 所需。
用户已裁决简化 A-2、A-3；PRD §5.4.1 与架构 §3.2.6、§4.4 已同步。

## 决策 (Decision)

- MVP（Phase 0）只保留 `{id}.json` 当前草稿，支持查看、编辑、保存与删除。
- `version` 自增与 `expectedVersion` 乐观锁继续用于并发控制，不表示保存了可回溯历史。
- 不创建版本快照目录或历史数组，不提供历史列表、历史查看或恢复接口。
- 固定目录与按绝对文件路径归属的写锁内，写临时文件后 `rename` 原子替换当前文件。
- 替换前写入失败不覆盖当前文件，不谎报成功；继续使用统一存储错误边界。
- 发布 URL 的服务端治理字段与全渠道不变量保持不变；没有恢复入口可以绕过发布守卫。
- 运营指标历史仍保留，用于环比；它不属于此次草稿历史简化范围。

## 后果 (Consequences)

保存只涉及当前草稿的一个持久文件，不需要当前文件与版本快照的双文件提交或补偿。
用户保存成功后无法通过产品回看旧内容，这是 MVP 明确接受的限制。
此次只同步文档，不改写或删除用户现有数据，也不把单文件原子替换描述成断电持久性保证。
若未来需要历史能力，须另行定义需求、发布凭据恢复语义与故障一致性契约，再提出实现变更。

## 合规性 (Compliance)

- 保留固定目录、串行写锁、乐观锁、原子写入与 `drafts/storage-unavailable`。
- MVP 不提供 `drafts.listVersions` / `drafts.getVersion` / `drafts.restoreVersion`。
- 删除当前草稿不承诺旧历史文件清理或远端文档联动删除。
